# 9.5.6 Watch Items And Alerts Foundation

Status: Complete

## Goal

Give VerityDesk a local-first way to remember specific signals the user cares about and flag them when daily reports contain matching evidence.

## What Changed

- Added local `watch_items` and `watch_alerts` tables.
- Added API routes for listing, creating, editing, deleting, and evaluating watch items.
- Added daily workflow evaluation after daily topic panels are generated.
- Reworked the Watchlist screen so users can add plain-English watch items and see alert status.
- Kept company deep-dive report generation available below the watch item area.

## Initial Behavior

Users can add watch items like:

- `Phoenix inventory rising`
- `Mortgage rates below 6.5`
- `Fed cut odds changing`
- `NVDA earnings catalyst`

When watch items are checked, VerityDesk scans recent saved generated reports. If a watch item matches a report, it marks the item as `Alert` and creates a local alert record. Duplicate alerts are avoided for the same watch item and report.

## Manual Steps

None.

## Current Limitation

The first version uses keyword-style matching against saved reports. A later version should evaluate thresholds and meaning with structured metrics plus an LLM classifier, then support desktop notifications or menu bar alerts.

## Validation

- Backend tests cover watch item alert creation and duplicate prevention.
- Endpoint tests cover the create/list round trip.
- Full frontend checks should confirm the Watchlist tab compiles.
