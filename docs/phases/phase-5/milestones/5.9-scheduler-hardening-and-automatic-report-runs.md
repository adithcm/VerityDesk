# Milestone 5.9: Scheduler Hardening And Automatic Report Runs

Status: Complete

## Goal

Persist schedule settings and support automatic local daily ingestion/report generation when the app is running.

## Deliverables

- Persisted scheduler configuration.
- Last run, next run, scheduler status, last message, and generated report tracking.
- Automatic daily ingestion trigger when enabled and the backend is running.
- Optional automatic daily briefing generation after ingestion.
- UI status for scheduled time, last run, next run, generated report, and automation mode.
- Tests for scheduler config, persistence, next-run calculation, and trigger decisions.

## Implementation Notes

- Scheduler settings are stored in the local `user_settings` table.
- The backend starts a lightweight background scheduler loop on app startup.
- The loop checks whether the configured local daily run is due and runs ingestion once per scheduled day.
- Users can enable or disable automatic daily runs and automatic daily briefing generation from Settings.
- The Dashboard shows whether automation is on, when it last ran, when it will run next, and the last generated report ID.
- The local startup path runs migrations, so the scheduler columns are applied through `make app-dev`.

## Definition Of Done

- Scheduler settings survive backend restart.
- When enabled, the app can trigger the daily workflow without manual button clicks while the local backend is running.
- The UI clearly shows whether automation is on and when data/report generation last ran.
