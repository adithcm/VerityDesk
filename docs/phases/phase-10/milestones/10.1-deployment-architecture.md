# Milestone 10.1: Deployment Architecture

Status: Complete

## Goal

Define the first deployable shape for VerityDesk before adding packaging code.

## Decisions

- First deployment target: macOS desktop app.
- App name: VerityDesk.
- Desktop shell: Electron for the first packaging pass because it can wrap the existing Next.js UI and supervise the FastAPI backend with the least rewrite.
- Development database: Postgres remains supported through Docker/Postgres.app.
- Packaged desktop database: app-managed local database file, so a normal user does not need Docker or Postgres.
- Cloud/multiuser future: hosted Postgres can be used later by changing `DATABASE_URL`.
- Backend startup: desktop shell starts the Python backend process.
- Frontend startup: desktop shell opens the packaged frontend in an app window.
- Migrations: packaged app runs Alembic migrations on startup before serving the app.
- API keys: keep keys out of frontend code. Packaged app will read them from local backend config/env in a later milestone.

## Runtime Modes

| Mode | Database | Startup | Intended user |
| --- | --- | --- | --- |
| Developer local | Postgres or SQLite via `DATABASE_URL` | `make app-dev` | Builder/developer |
| Packaged desktop | Local app-managed database file | `VerityDesk.app` | Normal local user |
| Future cloud | Hosted Postgres | Deployed service | Shared/multi-device users |

## Data Locations

Final exact paths are implemented in milestone 10.3, but the target layout is:

- App data: `~/Library/Application Support/VerityDesk/`
- Database: `~/Library/Application Support/VerityDesk/veritydesk.db`
- Logs: `~/Library/Logs/VerityDesk/`
- Local config/API keys: `~/Library/Application Support/VerityDesk/config.env`

## Acceptance Criteria

- Deployment architecture is documented.
- Phase 10 roadmap exists.
- Later milestones have clear constraints: no Docker requirement for packaged desktop, preserve dev Postgres support, and keep user data outside app code.
