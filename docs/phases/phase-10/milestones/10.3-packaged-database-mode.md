# Milestone 10.3: Packaged Database Mode

Status: Complete

## Goal

Make the desktop runtime use an app-managed local database path while preserving the existing development database options.

## What Changed

- Electron now resolves desktop runtime paths on startup.
- Electron creates the app data and log directories if they do not already exist.
- Electron passes `DATABASE_URL` into Alembic and FastAPI.
- Alembic migrations run against the desktop database before the backend starts.
- Dev Postgres remains unchanged because `make app-dev` still reads `.env` normally.

## Desktop Runtime Paths

Default macOS paths:

```text
Data: ~/Library/Application Support/VerityDesk/
Database: ~/Library/Application Support/VerityDesk/veritydesk.db
Logs: ~/Library/Logs/VerityDesk/
```

Developer override variables:

```bash
VERITYDESK_DESKTOP_DATA_DIR=/tmp/veritydesk-data
VERITYDESK_DESKTOP_LOG_DIR=/tmp/veritydesk-logs
VERITYDESK_DESKTOP_DATABASE_URL=sqlite:////tmp/veritydesk-data/veritydesk.db
```

## How To View The Desktop Database

For the packaged/local desktop database, open the SQLite file in DBeaver:

1. Create a new SQLite connection.
2. Select the database file:
   `~/Library/Application Support/VerityDesk/veritydesk.db`
3. Open the tables after the desktop app has launched at least once.

Development Postgres can still be viewed with the existing DBeaver Postgres connection.

## Acceptance Criteria

- Desktop shell sets a local database path automatically.
- Migrations run before backend startup.
- Existing `make app-dev` and Postgres workflow remain intact.
- User data lives outside app code so it can survive future app updates.
