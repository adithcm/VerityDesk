# Milestone 10.4: API Key And Local Config Handling

Status: In progress

## Goal

Let the desktop app read API keys from a local machine config file without exposing them in frontend code.

## Decision

For the first deployment, VerityDesk uses a local `config.env` file:

```text
~/Library/Application Support/VerityDesk/config.env
```

This is simpler than building a full in-app key manager now. A later phase should move secrets into macOS Keychain or an encrypted app-managed credential store.

## What The Desktop Shell Does

- Creates the app data directory if needed.
- Creates `config.env` with placeholder keys if it does not already exist.
- Reads key/value pairs from `config.env`.
- Passes those values to the backend and migration processes as environment variables.
- Keeps API keys out of the Next.js frontend bundle.

## Supported Keys

```bash
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5-mini
TAVILY_API_KEY=
LIVE_WEB_SEARCH_PROVIDER=tavily
FRED_API_KEY=
CENSUS_API_KEY=
ALPHA_VANTAGE_API_KEY=
FINNHUB_API_KEY=
NEWSAPI_KEY=
GDELT_API_KEY=
OWNER_EMAIL=
INVESTORAGENT_USER_AGENT=VerityDesk/0.1 contact@example.com
```

## Security Notes

- This file is local to the macOS user account.
- It should not be committed to GitHub.
- It is acceptable for the first local deployment but is not the final security model.
- Future improvement: macOS Keychain-backed storage and an in-app key setup page.

## Acceptance Criteria

- Desktop runtime has a config file path.
- Desktop runtime creates a placeholder config file when missing.
- Desktop runtime loads config variables before starting backend services.
- Documentation tells the user where to fill in keys.
