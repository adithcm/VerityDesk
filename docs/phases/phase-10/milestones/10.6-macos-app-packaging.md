# Milestone 10.6: macOS App Packaging

Status: Complete

## Goal

Create the first clickable macOS `.app` bundle for VerityDesk.

## What Changed

- Added `electron-builder` packaging.
- Added a generated macOS `.icns` app icon from the approved VerityDesk mark.
- Added `make desktop-pack-mac` to build a local `.app` directory.
- Added `make desktop-dist-mac` as the later DMG packaging path.
- Updated the desktop runtime to use packaged resource paths when running inside the `.app`.
- The packaged app includes:
  - Electron shell.
  - FastAPI backend code.
  - Alembic migrations.
  - Built Next.js frontend.
  - Frontend dependencies needed by `next start`.
  - Local Python environment.
  - Local Node runtime.

## Build Command

```bash
make desktop-pack-mac
```

Output:

```text
desktop/dist/mac-arm64/VerityDesk.app
```

## Security / Secret Handling

- The built app does not include `.env`, `.env.local`, or `config.env`.
- Desktop API keys remain in:
  `~/Library/Application Support/VerityDesk/config.env`
- `desktop/dist/` is ignored and should not be committed.

## Current Limitations

- The app is unsigned because no valid Apple Developer ID signing identity is configured.
- macOS may require right-click Open or System Settings approval.
- The app is large because it currently bundles local Python, Node, backend, frontend, and dependencies.
- DMG distribution and signing/notarization are later polish steps.

## Acceptance Criteria

- A `.app` bundle is generated locally.
- The app uses the approved VerityDesk icon.
- Build output is ignored by Git.
- Secrets are not packaged or committed.
