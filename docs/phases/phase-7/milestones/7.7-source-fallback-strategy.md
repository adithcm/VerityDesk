# Milestone 7.7: Source Fallback Strategy

Status: Complete

## Goal

Make source retrieval more resilient by defining what happens when local evidence is missing, stale, or too thin.

## Scope

- Uses local stored data first.
- Detects when local evidence is missing or too thin for the agent query.
- Reads source health so agents can name stale, failed, skipped, or not-configured sources.
- Records the source path in agent claims and LLM-facing evidence.
- Returns a clearer explanation when an answer cannot be supported.
- Adds national-vs-local fallback language for regional mortgage-rate questions.
- Prepares Phase 8 live retrieval by making source gaps explicit before the app tries external lookup.

Phase 7.7 does not implement the full live web research agent. That is explicitly planned for Phase 8.5.

## Fallback Order

1. Use local stored articles and structured observations.
2. Check expected source health for the selected specialist agent.
3. If matching evidence exists, answer from that local evidence and include coverage notes.
4. If local evidence is missing, say which local path was checked and what source health is known.
5. If the request is regional but only national mortgage-rate data is available, label it as national context.
6. Defer live web lookup to Phase 8.5, where source allowlists, citations, and storage rules will be implemented.

## Expected Behavior

For a question like "What are mortgage rates in AZ?", the system should:

- search local evidence
- check freshness
- report connected mortgage/housing source health
- answer with the best available evidence
- clearly say if only national data is available

## Tests

- Fresh local evidence path.
- Stale source-health coverage gap.
- Missing local evidence path.
- Failed source-health reporting.
- National-only regional mortgage-rate fallback note.
- No-supported-answer behavior.

## Definition Of Done

- The app has a documented source fallback order.
- Agents have better evidence availability for Phase 8 flexible retrieval.
- Unsupported answers are clear instead of vague.
- Agent output now carries a source-path claim.
- LLM prompts now include a source fallback summary.

## Phase 8 Handoff

Phase 8.5 should implement the actual controlled Live Web Research Agent. It should use the 7.7 fallback summary as its trigger:

- local evidence missing
- local evidence stale
- provider failed/rate-limited
- only national context available for a local question
- direct source/API retrieval cannot answer the question
