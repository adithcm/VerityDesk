# Milestone 4.3: Domain Agent Implementations

Status: Complete

## Goal

Implement the first real domain agents that analyze Phase 3 data.

## Deliverables

- `NewsDigestAgent` for broad daily news context.
- `CompanyAgent` for company and ticker-focused research.
- `MarketAgent` for market/rates context.
- `MacroAgent` for macroeconomic indicators.
- `HousingAgent` for housing and real estate context.
- Shared output format across agents.
- Tests for each agent using seeded or mocked evidence.

## Implemented

- Added `backend/app/agents`.
- Added `NewsDigestAgent`.
- Added `CompanyAgent`.
- Added `MarketAgent`.
- Added `MacroAgent`.
- Added `HousingAgent`.
- Added shared `EvidenceBackedDomainAgent`.
- Added `DomainAgentConfig` for each specialist's focus, domains, series IDs, and default time window.
- Added `build_domain_agents` factory.
- Added `TemplateResearchSummarizer` fallback for deterministic local/test behavior.
- Added `OpenAIResearchSummarizer` for model-backed summaries when `OPENAI_API_KEY` is configured.
- Added `OPENAI_MODEL`, defaulting to `gpt-5-mini`.
- Added tests for all domain agents and response text extraction.

## Definition Of Done

- Each domain agent can produce a structured, cited partial answer from available evidence.
- Missing-data states are handled clearly.

## Validation Results

- Backend tests passed: 68 passed.
- Backend lint passed.

## Notes

- The domain agents can now produce partial source-backed results, but the main query endpoint still runs the coordinator placeholder until Milestone 4.4 wires routing and synthesis.
- Model-backed summaries use the OpenAI Responses API when configured. If the key is missing or the API call fails, agents fall back to deterministic summaries so local development remains stable.
- The first implementation uses a shared prompt builder. Later Phase 4 work should split prompts into explicit templates for each domain agent, coordinator synthesis, citation formatting, and guardrail review.
