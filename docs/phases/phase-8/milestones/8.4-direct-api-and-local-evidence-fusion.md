# Milestone 8.4: Direct API And Local Evidence Fusion

Status: Complete

## Goal

Make the normal agent chat use a fused research packet that combines live web search, direct API-backed data, locally cached records, and saved reports before the LLM writes the answer.

This milestone is the bridge between "the planner knows web research is needed" and "the user actually gets a web-first, citation-backed answer."

## What Changed

- Added an evidence packet contract for ranked research items and retrieval statuses.
- Added an evidence fusion service that collects:
  - Tavily live web results
  - direct API-backed evidence from connected providers
  - locally cached articles and economic observations
  - relevant saved reports
- Ranked evidence by:
  - retrieval channel, with live web first
  - source quality
  - relevance
  - recency
- Added citation deduping across specialist agents and fused evidence.
- Fed the fused evidence packet into the synthesis prompt.
- Added an internal `EvidenceFusionAgent` step to the agent response trace.
- Kept missing Tavily configuration graceful: the packet records the skipped live web search and continues with API/local evidence.

## Intended Behavior

When the user asks a flexible or current question, the app should:

1. Understand the question.
2. Generate web and API/local retrieval needs.
3. Search Tavily when `TAVILY_API_KEY` is configured.
4. Pull supporting records from direct APIs and local cache.
5. Add relevant saved reports as internal context.
6. Rank the evidence together.
7. Give the LLM the fused packet first, before specialist summaries.

This supports the desired flow where web research is the primary flexible answer source, while APIs and local stored data are still used as verification and context.

## Manual Step

The user needs to add a Tavily API key before live web search can run:

```bash
TAVILY_API_KEY=your-key-here
LIVE_WEB_SEARCH_PROVIDER=tavily
```

Without the key, the app still works but live web search is marked as skipped.

## Tests Added

- Evidence packet fuses live web, direct API, local cache, and saved reports.
- Live web evidence ranks before supporting API/local evidence.
- Missing Tavily key or skipped live web retrieval is captured in retrieval status.
- Synthesis evidence includes the fused packet and retrieval statuses.
- Agent endpoint test avoids real Tavily calls during automated test runs.

## Handoff To 8.5

Milestone 8.5 should make specialist agents consume the ranked packet directly instead of doing their own local-only evidence lookups. This will reduce duplicated retrieval logic and make routing more automatic and less dependent on manual dropdown/context selection.
