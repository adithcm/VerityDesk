# Milestone 8.5: Automatic Agent Routing And Multi-Agent Execution

Status: Complete

## Goal

Make specialist agents consume the ranked evidence packet from Milestone 8.4 instead of acting like separate local-only database readers.

This keeps the app moving toward the desired Codex-like behavior: the user asks one plain-language question, Tavily searches the current web first, APIs/local data support the answer, and the specialist agents interpret the same shared evidence.

## What Changed

- Added the fused evidence packet to the shared agent context for each request.
- Updated specialist agents to prefer evidence packet items when available.
- Made live web evidence available to every relevant specialist because the Tavily queries are generated from the user's actual question.
- Kept API/local evidence in the packet as verification, context, and structured data.
- Preserved the older local-only lookup path as a fallback when no packet evidence is available.
- Added packet-based claims, risks, citations, and confidence scoring for specialist agents.
- Logged the packet in agent context so the run history can show what the agent had available.

## Intended Behavior

For a question like "What is happening with housing in Arizona?", the flow should now be:

1. The coordinator infers this is a housing/regional/current question.
2. Tavily searches the web for current Arizona housing context.
3. Direct/local data such as FHFA, FRED, Freddie Mac, Census, and cached news are added when available.
4. The evidence fusion layer ranks the evidence.
5. HousingAgent receives the ranked packet directly.
6. HousingAgent summarizes from the web-first packet, with API/local evidence used to verify or quantify.
7. The final synthesis agent writes the user-facing answer from the same packet and specialist summaries.

## Manual Step

No new manual key is required for this milestone.

Tavily must be configured for live web search:

```bash
TAVILY_API_KEY=your-key-here
LIVE_WEB_SEARCH_PROVIDER=tavily
```

If Tavily is not configured or a search fails, agents still run from API/local evidence, but the answer should say current web evidence was unavailable.

## Tests Added

- Specialist agent prefers the fused packet when it includes Tavily live web evidence.
- Specialist agent can use live web and direct API evidence together.
- Existing local-only specialist tests still pass, proving the fallback path remains intact.

## Handoff To 8.6

Milestone 8.6 should clean the final user-facing answer. The current architecture now gives the LLM better evidence, but the wording still needs to become much simpler: direct answer first, fewer internal agent labels, fewer raw risk/debug bullets, and clearer source-backed takeaways.
