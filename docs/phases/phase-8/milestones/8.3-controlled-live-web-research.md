# Milestone 8.3: Controlled Live Web Research

Status: Complete

## Goal

Add the first real live web research layer so the Phase 8 planner can move toward web-first answers. This milestone creates a provider-agnostic backend service, implements Tavily as the first provider adapter, and returns citation-ready evidence that later milestones can fuse with API/local data and feed into specialist agents.

## Provider Choice

First provider: Tavily.

Reasoning:

- Tavily is built for AI/web research workflows.
- It provides search results with excerpts that are suitable for LLM grounding.
- It has a straightforward REST API.
- It offers a free API key tier suitable for local development.
- The app keeps a provider boundary so Brave Search, Exa, SerpAPI, or another provider can be added later.

## Implemented

- Added `TAVILY_API_KEY` and `LIVE_WEB_SEARCH_PROVIDER` settings.
- Added live web schemas:
  - `LiveWebSearchRequest`
  - `LiveWebSearchResponse`
  - `LiveWebEvidence`
  - `LiveWebCitation`
- Added a Tavily-backed live web research service.
- Added source-quality classification:
  - primary
  - reputable
  - provider
  - discovery
- Added blocked-domain handling for low-signal/social domains.
- Added include/exclude domain controls.
- Added backend endpoint:

```http
POST /api/v1/agents/live-web/search
```

- Added citation-ready output with:
  - title
  - URL
  - publisher/domain
  - published date when provided
  - retrieved timestamp
  - excerpt
  - source quality
  - supported-claim text

## Manual Steps

To enable live web search locally, add this to `.env`:

```text
TAVILY_API_KEY=your-key-here
LIVE_WEB_SEARCH_PROVIDER=tavily
```

Get the key from:

- Tavily platform/dashboard: `https://app.tavily.com`
- Tavily quickstart docs: `https://docs.tavily.com/documentation/quickstart`

If the key is missing, the endpoint returns a clean skipped response instead of failing the app.

## What This Does Not Implement Yet

- Full agent orchestration that automatically calls live web search during normal chat.
- Evidence fusion between web, API, and local records.
- LLM prompt changes that use live web evidence in the final answer.
- Frontend UI for showing whether an answer used live web.
- Broader provider adapters such as Brave Search or Exa.
