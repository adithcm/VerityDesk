# Milestone 8.9: Phase 8 Validation And Docs

Status: Complete

## Goal

Validate that Phase 8 delivers the web-first agent framework direction and document the operating rules for future phases.

This milestone closes the intelligence rebuild by making sure the app can answer flexible questions with Tavily-first evidence, API/local support, clean synthesis, personalization, citations, and guardrails.

## What Changed

- Added Phase 8 regression tests for flexible real-world questions:
  - "What is happening with housing in Arizona?"
  - "What are mortgage rates in AZ?"
  - "What matters for my watchlist today?"
  - "What changed with Apple this week?"
  - broad market questions where local data is thin
- Added validation that normal answers:
  - include live web citations when Tavily evidence exists
  - include `EvidenceFusionAgent` in the internal agent trace
  - avoid coordinator/debug/source-path text in the visible summary
  - preserve financial guardrails
- Added validation that a Tavily miss or missing key can still fall back to API-backed evidence where available.
- Added a dedicated web research policy doc covering:
  - what Tavily/live web can do
  - what it cannot guarantee
  - source quality rules
  - storage policy
  - answer policy
- Updated the Phase 8 README status and milestone links.

## Phase 8 Acceptance Criteria

Phase 8 is complete when:

- User questions can be understood without manual dropdowns.
- Current/broad/local questions prioritize Tavily live web search.
- Direct APIs and local evidence are fused as support.
- Specialist agents consume the shared fused evidence packet.
- Final answers are concise and hide raw internal mechanics.
- Saved preferences can shape broad questions and daily briefings.
- Daily briefings use the same Tavily-first personalized flow.
- Guardrails still prevent direct financial advice.
- Regression tests cover the known problem cases.

## Handoff To Phase 9

Phase 9 should focus on UI, prompting, and product cleanup now that the intelligence foundation is in place.

The main Phase 9 goals should be:

- simplify the screen layout
- reduce visible lists and internal details
- make the question box the primary user workflow
- expose preferences in a friendly way
- show citations and retrieval details behind secondary controls
- tune prompts and answer style after live testing with real Tavily/OpenAI responses
- add Tavily credit controls so normal questions default to one lower-cost search, while deeper daily briefing or explicit deep-dive questions can use broader search
- make the app feel polished enough before desktop packaging
