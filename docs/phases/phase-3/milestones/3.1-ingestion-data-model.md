# Milestone 3.1: Ingestion Data Model

Status: Complete

## Goal

Add the database foundation needed to track what InvestorAgent fetches, where it came from, when it was retrieved, whether the source is fresh, and how duplicates can be detected.

## Included

- `ingestion_runs` table for per-source fetch attempts.
- `source_health` table for freshness, failure, and latest-item status.
- `retrieved_snapshots` table for retrieval metadata, content hashes, excerpts, response headers, and storage policy.
- `external_ids` table for source-specific IDs that help deduplicate articles and structured observations.
- SQLAlchemy model relationships from sources, articles, and economic observations into ingestion records.
- Alembic migration `0002_ingestion_data_model.py`.
- Tests proving the model metadata, relationships, and migrations create the expected tables.

## Not Included Yet

- Fetching real RSS feeds.
- Calling official APIs.
- Deduplication service logic.
- Source scheduling.
- Health/freshness API endpoints.
- Frontend ingestion controls.

Those are covered by later Phase 3 milestones.

## Definition Of Done

- Ingestion tables are represented in SQLAlchemy metadata.
- A clean database can migrate through Alembic to include the ingestion tables.
- Ingestion run, source health, snapshot, and external ID records can be inserted and related to source/article records.
- Backend tests and lint pass.
