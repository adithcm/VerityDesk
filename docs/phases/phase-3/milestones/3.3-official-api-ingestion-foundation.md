# Milestone 3.3: Official API Ingestion Foundation

Status: Complete

## Goal

Add the first official API and dataset ingestion foundation so InvestorAgent can pull structured or source-authoritative data beyond RSS feeds.

## Included

- Official API ingestion service.
- Manual local command: `make official-api-ingest`.
- SEC company submissions connector foundation using `data.sec.gov`.
- FRED observations connector foundation with API-key checking.
- Census connector scaffold with API-key checking.
- FHFA dataset connector scaffold.
- Freddie Mac PMMS dataset connector scaffold.
- SEC filing metadata persistence into article records.
- FRED observation normalization into `economic_observations`.
- External ID tracking for SEC accession numbers and economic observations.
- Ingestion run logging for success, skipped, and failed sources.
- Source health updates for fresh, skipped, and failed states.
- Tests for SEC normalization, FRED normalization, missing API keys, persistence, deduplication, and scaffolded dataset connectors.

## Source Access

Default source behavior:

- SEC data APIs: public and no API key required.
- FRED API: requires `FRED_API_KEY`.
- U.S. Census API: requires `CENSUS_API_KEY`.
- FHFA HPI: public dataset source scaffolded for a later parser pass.
- Freddie Mac PMMS: public dataset source scaffolded for a later parser pass.

## Manual Run

```bash
make official-api-ingest
```

Without API keys, SEC can ingest while FRED and Census skip cleanly and record the missing-key reason in source health.

## Not Included Yet

- Automatic scheduling.
- Backend ingestion endpoints.
- Frontend ingestion controls.
- Full FHFA dataset parser.
- Full Freddie Mac PMMS parser.
- Complete market-data provider integrations.

Those are covered by later Phase 3 milestones.

## Definition Of Done

- SEC company submissions can be fetched and stored without an API key.
- Key-required sources skip cleanly when local keys are missing.
- Structured observations can be normalized and persisted.
- Duplicate official API records update existing rows instead of creating duplicates.
- Backend tests and lint pass.
