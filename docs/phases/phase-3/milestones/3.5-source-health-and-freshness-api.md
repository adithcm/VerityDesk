# Milestone 3.5: Source Health And Freshness API

Status: Complete

## Goal

Expose ingestion health, recent source runs, and latest ingested items through backend APIs so the frontend can show what data exists and whether it is fresh.

## Included

- `GET /api/v1/ingestion/health` endpoint.
- `GET /api/v1/ingestion/runs` endpoint.
- `GET /api/v1/ingestion/latest-items` endpoint.
- Source health response schemas.
- Ingestion run history response schemas.
- Latest item response schemas for articles and economic observations.
- Freshness calculation for `fresh`, `stale`, `failed`, `skipped`, and `not_configured`.
- Catalog-aware source health output so planned sources appear even before their first run.
- Recent ingestion run ordering.
- Latest article and economic observation listing.
- Tests for service behavior and endpoint wiring.

## API Shape

Health:

```http
GET /api/v1/ingestion/health
```

Recent runs:

```http
GET /api/v1/ingestion/runs?limit=50
```

Latest ingested items:

```http
GET /api/v1/ingestion/latest-items?limit=25
```

## Not Included Yet

- Frontend display of the new health data.
- Frontend ingestion run button.
- Automatic daily background trigger.
- Persistent schedule storage.

Those are covered by later Phase 3 milestones.

## Definition Of Done

- Backend exposes source health, run history, and latest item read APIs.
- Health API calculates stale status from `stale_after`.
- Planned catalog sources appear as `not_configured` before first run.
- Latest items include both news/article metadata and structured observations.
- Backend tests and lint pass.
