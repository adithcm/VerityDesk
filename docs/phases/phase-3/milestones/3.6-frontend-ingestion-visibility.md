# Milestone 3.6: Frontend Ingestion Visibility

Status: Complete

## Goal

Connect the frontend shell to ingestion health, recent runs, latest ingested items, and manual ingestion run controls.

## Included

- Dashboard ingestion health cards for fresh, stale, failed, skipped, and not configured sources.
- Manual ingestion run control for all sources, RSS only, or official APIs only.
- Latest ingested items list for articles and economic observations.
- Recent ingestion runs table.
- Sources page freshness status, last checked, last success, latest item, and source errors.
- Daily Briefing inputs view backed by latest ingested items.
- Settings page source count backed by ingestion health.
- Loading, empty, and error states for ingestion API calls.

## Not Included Yet

- Automatic daily background trigger.
- Rich generated daily briefing summaries.
- Editable scheduler settings in the frontend.
- Source-specific run buttons.
- Polished production UI.

Those are covered by later phases and the final Phase 3 validation pass.

## Definition Of Done

- Frontend reads ingestion health from `GET /api/v1/ingestion/health`.
- Frontend reads recent runs from `GET /api/v1/ingestion/runs`.
- Frontend reads latest items from `GET /api/v1/ingestion/latest-items`.
- Frontend can trigger ingestion through `POST /api/v1/ingestion/run`.
- Frontend typecheck and production build pass.
