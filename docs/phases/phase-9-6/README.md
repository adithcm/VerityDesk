# Phase 9.6: Option M Visual Product Implementation

Status: Complete

## Goal

Implement the approved Option M product direction before desktop deployment.

Option M turns VerityDesk from a text-heavy dashboard into a visual daily intelligence app:

- direct APIs and stored source data power visual modules, metrics, drill-downs, and source freshness
- Tavily and the agent framework power flexible questions, explanations, and source-backed answers
- the LLM explains visuals and daily signals instead of being the only interface
- the home screen stays simple and useful without forcing users through many tabs

Reference mockup:

- [Option M Interactive Flow](../phase-9-5/design-options/option-m-interactive-flow.html)

## Product Shape

Primary tabs:

- `Home`
- `Daily Brief`
- `Agent Chat`
- `Settings`

The app should avoid unnecessary visible tabs. Operational details such as sources, saved reports, source health, watch items, and refresh controls should live inside Settings, drill-downs, or compact drawers unless the user explicitly opens them.

## Home

The Home page should keep the Option M layout:

- left rail with profile summary and quick status
- large visual dashboard surface
- source/API-powered visual modules
- one ask bar
- minimal words
- no badge-heavy card clutter

Home modules should be visual first:

- `Daily Read`
- `Housing`
- `Markets`
- `Companies`
- `Macro`

Each visual module should use connected API/source data where possible:

- FRED, Freddie Mac, FHFA, Census for housing and macro visuals
- Alpha Vantage, Finnhub, NewsAPI, SEC for market/company/watchlist visuals
- stored ingestion metadata for freshness and source health
- report metadata for signal/change state
- watch item metadata for alert state

Clicking a visual module should open a drill-down view with:

- a larger chart or metric visualization
- key stats
- source timestamps
- concise interpretation
- hidden detailed citations/source rows
- `Ask About This`, which opens Agent Chat with the visual context attached
- optional `Add To Daily Brief`

## Daily Brief

Daily Brief should be a dedicated page with a markdown-style AI brief that is autogenerated from:

- the user's saved profile
- Tavily live web research
- connected API metrics and source data
- saved watch items
- source freshness/status

The brief should cover the user's important areas, such as:

- world news and geopolitics
- markets
- macro and rates
- housing
- company/watchlist news
- commodities/energy
- regulation and policy
- consumer/labor/credit

The format should be simple:

- `## Bottom Line`
- `## What Changed`
- `## Major Trends`
- `## Why It Matters To You`
- `## What To Watch`
- `## Confidence And Gaps`

Sources and citations should be hidden by default and available through a drawer.

## Agent Chat

Agent Chat should behave more like ChatGPT/Codex:

- active chat and previous chats appear on the same page
- previous sessions are visible in a sidebar
- selecting a previous chat loads the saved summary/context
- `New Chat` starts a clean thread while preserving saved user profile
- the active session has memory of earlier messages in that session
- asking from Home moves focus into Agent Chat automatically
- asking from a visual drill-down attaches that visual's metric/source context

The agent should use:

- Tavily/live web as the flexible discovery layer
- stored direct API data as structured evidence
- user profile and settings as personalization
- guardrails and disclaimer language for investment-related answers

## Login And Setup

Add an official-looking login and setup experience.

For local desktop, implementation can remain local-first at first:

- local profile identity
- optional local passcode placeholder
- stored preferences on this machine
- clear future path to cloud login/sync

For deployment, the app should move user-specific data into a backend database tied to login. That includes profile details, preferences, saved chats, daily brief settings, source configuration, watch items, visual preferences, and acknowledgement state.

Setup should collect:

- name/profile label
- location and housing markets
- watchlist tickers and companies
- sectors/topics of interest
- personal note/goals
- answer style preference
- daily brief schedule
- source/API status

The first run should guide the user from Login/Setup into Home.

## Settings

Settings should hold complexity so Home stays simple:

- profile
- daily brief schedule
- source/API status
- refresh controls
- watch item configuration
- saved reports/source details
- model/provider status
- disclaimer/settings acknowledgements

Settings can expose the deeper operational information that should not clutter the default user experience.

## Visual Data Layer

Create a frontend-friendly visual data contract so modules do not depend directly on raw report text.

Suggested backend response shape:

- module id
- title
- value
- subtitle
- trend direction
- chart points
- source freshness
- source list
- related report id
- related watch item ids
- suggested agent prompt

The UI should gracefully handle missing data:

- `Needs Refresh`
- `Source Not Connected`
- `No Local Data Yet`
- `Ask Agent`

Avoid generic repetitive labels such as every card saying `Developing`.

## Definition Of Done

- The default app opens to a simple visual Home based on Option M.
- The user sees useful visuals powered by connected APIs/source data.
- Each visual can be opened for deeper stats and source freshness.
- The user can ask about any visual and continue in Agent Chat.
- Agent Chat has active session memory and visible previous chats.
- Daily Brief is a dedicated markdown-style AI brief.
- Login/setup exists and leads naturally into the app.
- Settings contains complexity instead of the Home screen.
- Main navigation is simple and not tab-heavy.
- The implementation is ready to flow into desktop deployment.
