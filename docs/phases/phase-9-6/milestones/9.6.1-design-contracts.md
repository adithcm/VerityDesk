# 9.6.1 Design Contracts

Status: Complete

## Goal

Turn the approved Option M mockup into implementation contracts before changing the app.

## Scope

- Preserve [Option M Interactive Flow](../../phase-9-5/design-options/option-m-interactive-flow.html) as the design reference.
- Define the frontend view map:
  - Login
  - Setup
  - Home
  - Daily Brief
  - Agent Chat
  - Settings
  - Visual drill-down
- Define the visual module data contract.
- Define how Home asks, visual drill-down asks, and Daily Brief asks pass context into Agent Chat.
- Define empty, stale, missing-key, and source-not-connected states.

## Deliverables

- A documented visual module schema.
- A documented routing/state model.
- A list of backend fields required by the Option M Home and drill-downs.
- A list of existing app pieces that can be reused.

## View Contract

Primary app views:

| View | Purpose | Notes |
| --- | --- | --- |
| `login` | Official entry point | Local-first placeholder until real cloud auth exists. |
| `setup` | First-run profile capture | Saves local profile and leads to Home. |
| `home` | Option M visual dashboard | Default view after setup/login. |
| `daily_brief` | Autogenerated markdown brief | Uses profile, live web, APIs, watch items, and source health. |
| `agent_chat` | Flexible Q&A | Includes active session and previous chats in one view. |
| `settings` | Operational/control surface | Holds profile, sources, refresh, watch items, schedule, provider/key state. |
| `drilldown` | Visual detail view | Opened from Home visual modules. |

## Visual Module Contract

The backend should return visual modules using a frontend-friendly shape:

```json
{
  "id": "housing",
  "title": "Housing",
  "summary": "Mortgage rates and affordability remain the key pressure points.",
  "primary_value": "6.7%",
  "primary_label": "30Y fixed mortgage",
  "status": "watch",
  "trend": "mixed",
  "updated_at": "2026-09-14T08:00:00Z",
  "chart": {
    "kind": "bar",
    "points": [
      { "label": "May", "value": 35 },
      { "label": "Jun", "value": 48 }
    ]
  },
  "stats": [
    { "label": "FHFA YoY", "value": "+3.1%", "detail": "latest release" }
  ],
  "sources": [
    {
      "name": "FRED",
      "status": "fresh",
      "retrieved_at": "2026-09-14T08:00:00Z",
      "description": "Mortgage-rate series"
    }
  ],
  "related_report_id": 123,
  "related_watch_item_ids": [1, 2],
  "suggested_prompt": "Explain the housing visual in plain English for my profile."
}
```

Allowed module ids for the first implementation:

- `daily_read`
- `housing`
- `markets`
- `companies`
- `macro`

Allowed status values:

- `ready`
- `high_signal`
- `watch`
- `quiet`
- `needs_refresh`
- `source_not_connected`
- `no_local_data`

Avoid using `Developing` as the default fallback. Prefer explicit states such as `Needs Refresh`, `No Local Data`, or `Source Not Connected`.

## Context Handoff Contract

Home ask:

- source view: `home`
- payload: user question, profile context, active visual summaries
- destination: `agent_chat`

Visual drill-down ask:

- source view: `drilldown`
- payload: selected module id, stats, chart points, source freshness, suggested prompt
- destination: `agent_chat`

Daily Brief ask/follow-up:

- source view: `daily_brief`
- payload: current brief id/report id, section title, source/citation context
- destination: `agent_chat`

## Existing Pieces To Reuse

- Existing report generation endpoints.
- Existing source health and ingestion status endpoints.
- Existing watch items and alerts foundation.
- Existing markdown renderer and hidden citation drawers.

## Backend Fields Needed

- source freshness and timestamps from ingestion health
- latest structured economic observations
- latest articles/news by source/domain/ticker/region
- latest generated reports and report metadata
- watch item alert state
- user preferences/profile
- report citations for expandable source detail
