# Milestone 6.1: UI Information Architecture Cleanup

Status: Complete

## Goal

Make the first screen simpler, calmer, and closer to the way a user actually wants to use the product.

The Dashboard should feel like a personal intelligence desk. It should not feel like a developer console with source tables, ingestion history, and operational details competing for attention.

## User Feedback Addressed

- The Dashboard had too much information on screen.
- Long lists made it hard to see what mattered.
- Source health, latest ingested items, and recent runs were useful but too prominent.
- The user wants the normal flow to be question-first, with fewer controls and less manual setup.
- Technical details should remain available, but not on the default first screen.

## Implemented Changes

- Reworked the Dashboard around three primary actions:
  - ask a question
  - open the daily briefing
  - view saved reports
- Added a compact "Today At A Glance" status area with:
  - source summary
  - daily run state
  - next run
  - last run
- Added a Latest Briefing preview instead of showing long raw source lists.
- Added Quick Questions that route the user into Agent Chat without changing dropdowns first.
- Kept proactive suggestions on the Dashboard, but below the simpler starting area.
- Moved detailed source health, manual ingestion controls, latest ingested items, recent runs, and scheduler status into the Sources view.

## Product Behavior

The Dashboard should now answer:

- What can I ask?
- What was the latest useful output?
- What should I look at next?
- Is the system broadly working?

The Sources view should answer:

- Which sources are working?
- What was recently retrieved?
- When did ingestion last run?
- What needs technical attention?

- Milestone 6.3 will make the question box smarter by inferring intent, tickers, domains, regions, and time windows instead of requiring manual dropdowns.
